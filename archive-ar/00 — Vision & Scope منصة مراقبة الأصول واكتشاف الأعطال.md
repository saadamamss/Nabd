# 00 — Vision & Scope

**منصة مراقبة الأصول واكتشاف الأعطال (Asset Telemetry & Anomaly Detection SaaS)**

*Blueprint v0.1 — مسودة للمراجعة. مستند حي بيتعدل مع كل قرار.*

## 1. الغرض من الملف

ده أول ملف في الـ Blueprint. بيحدد **إيه المنتج، لمين، وإيه اللي جواه وإيه اللي برّا**. كل ملف بعده بيبني عليه، فأي قرار هنا بيتغير لازم نرجع نراجع الملفات اللي بعده.

قواعد القراءة:

- **قرار مفتوح (D#)** = محتاج رد منك، وجنبه الافتراضي اللي أنا مقترحه.
- أي رقم تقني هنا هو **هدف مبدئي**، بيتأكد أو بيتعدل في ملف المتطلبات (02) وملف الاختبار (09).
- أي "فرضية" معناها إنها محتاجة تتأكد بمقابلات عملاء حقيقيين، مش بالتفكير.

## 2. المشكلة

- شركات كتير عندها أصول غالية: مولدات، مضخات، ثلاجات ومخازن تبريد، معدات ثقيلة، أسطول.
- الصيانة غالبًا **دورية** (كل شهر مثلًا) أو **بعد العطل**، وكلاهما مش كفاية، لأن العطل بيحصل في أي لحظة بين موعدين.
- العطل بيكلّف: توقف إنتاج، إصلاح طارئ، بضاعة بتتلف، التزامات بتتكسر.
- البيانات اللي تنبّه بالمشكلة غالبًا **موجودة** (حساسات، عدادات، PLC) بس مش متجمعة ولا متحللة، أو الحلول الجاهزة غالية ومعقدة، أو منصات الـ Cloud العامة محتاجة فريق مهندسين يبني فوقها.
- النتيجة: الناس بتكتشف المشكلة **متأخر**.

## 3. الرؤية

> نخلّي أي شركة صغيرة أو متوسطة تعرف إن أصلها هيتعطل **قبل** ما يتعطل، من غير ما تبني منصة IoT بنفسها.

**التموضع (Positioning):** مش منصة IoT عامة. منتج **جاهز للاستخدام لقطاع واحد**، بيتركّب ويشتغل في أيام مش شهور، وبيدّي تنبيهات نضيفة مش لوحات معقدة.

**الفرق عن المنافسين الكبار:** هم بيبيعوا "مكعبات" (Building blocks) والعميل يبني. إحنا بنبيع **حل شغال** لمشكلة محددة بسعر وخدمة أقرب للعميل.

## 4. العميل المستهدف

### 4.1 اختيار القطاع الأول (D1)

القاعدة: **قطاع واحد في البداية.** "أي أصل في أي صناعة" معناه منتج مش مناسب لحد.

معايير المفاضلة:

| المعيار | ليه مهم |
| --- | --- |
| تكلفة التوقف على العميل | كل ما زادت، كل ما استعد يدفع |
| سهولة جمع البيانات | حساس جاهز وبروتوكول بسيط = MVP أسرع |
| عدد الأصول لكل عميل | يحدد حجم الاشتراك |
| قدرة العميل على الدفع | يحدد التسعير |
| قوة المنافسة في القطاع |  |
| وصولك الفعلي لعملاء | شبكة معارفك أهم من حجم السوق |

المرشحين للمقابلات الأولى (**كلهم فرضيات**):

| القطاع | فرضية مبدئية |
| --- | --- |
| سلاسل التبريد (ثلاجات/مخازن) | حساس حرارة بسيط وقاعدة تنبيه واضحة، وتكلفة التلف عالية. غالبًا أسهل MVP |
| المولدات والمضخات | قيمة الأصل عالية، بس الربط غالبًا عبر Controllers (Modbus) فأصعب تقنيًا |
| المعدات الثقيلة والأسطول | محتاج GPS وبيانات محرك، تنافس أكتر |
| تكييف وتبريد المباني (HVAC) | أصول كتير موزعة، بيانات متاحة أحيانًا من BMS |

**القرار:** منقررش بالتخمين. نقابل **8-10 ناس من 2-3 قطاعات**، ونختار على أساس الألم الحقيقي والاستعداد للدفع.

### 4.2 ملف العميل المثالي (ICP) — افتراض مبدئي

- شركة صغيرة أو متوسطة، من 20 لـ 500 أصل.
- فيها مسؤول صيانة أو عمليات، ومفيش فريق IT كبير.
- مستعدة تدفع اشتراك شهري لو شافت قيمة سريعة.

### 4.3 الشخصيات (Personas)

| الدور | بيحتاج إيه | بيقيس نجاح المنتج بإيه |
| --- | --- | --- |
| **مهندس/فني الصيانة** | تنبيه مبكر وواضح على الموبايل والإيميل، وتاريخ الأصل | عدد الأعطال المفاجئة اللي اتمنعت |
| **مدير العمليات** | نظرة شاملة على حالة الأصول وتقارير | وقت التوقف (Downtime) |
| **صاحب الشركة/الإدارة** | تكلفة أقل وتقارير بسيطة | التوفير المالي |
| **Tenant Admin** | يضيف أصول ومستخدمين ويظبط القواعد | سهولة الإعداد |
| **أنت (Platform Admin)** | يراقب كل العملاء والنظام | استقرار النظام وصحة الـ Pipeline |

## 6. النطاق (Scope)

### MVP — الهدف: يثبت القيمة مع عميل Pilot حقيقي

- Tenants + Users + Auth أساسي (Login + 3 أدوار).
- إدارة الأصول والحساسات.
- استقبال البيانات عبر **MQTT** و HTTP.
- هوية لكل جهاز (Token لكل جهاز، ويتلغي).
- تخزين Time-series.
- قواعد Threshold ثابتة + كشف انقطاع الجهاز.
- تنبيهات (Dashboard + Email) مع Deduplication و Cooldown.
- Dashboard حي + رسوم تاريخية.
- Device Simulator بيولّد حالات خلل مقصودة (Spike, Drift, Flatline, Dropout).
- Observability أساسي + Backups.
- عزل العملاء: TenantId + Row-Level Security.

### V1 — بعد نجاح الـ Pilot

Statistical detection (Z-score, EWMA)، Work Orders، Webhooks و SMS، تقارير وتصدير، Billing، Onboarding ذاتي، Edge Gateway (Store-and-forward)، Audit Logs، Rate limiting و Quotas لكل عميل.

### V2 وبعده

SSO (OIDC/SAML)، ML.NET، بروتوكولات صناعية (OPC UA, Modbus)، Predictive Maintenance (العمر المتبقي)، تطبيق موبايل، Public API و SDK، خيار Database مخصصة لعميل كبير، شهادات الامتثال.

### خارج النطاق (قرارات واعية)

- تصنيع Hardware أو حساسات خاصة.
- نظام CMMS كامل (مخزون قطع غيار، جدولة فنيين).
- تحليل فيديو أو صور.
- Microservices من البداية.
- أكتر من تطبيق موبايل.
- دعم كل بروتوكول في الدنيا.
- المنافسة كمنصة IoT عامة.

## 7. المبادئ الحاكمة

1. **القيمة قبل التقنية:** مفيش ميزة من غير سؤال "مين هيستخدمها؟".
2. **قطاع واحد** لحد ما ننجح فيه.
3. **Modular Monolith** مش Microservices.
4. **البيانات متضيعش:** أي قراءة اتأكد استلامها لازم تتخزن.
5. **الأمان وعزل العملاء من اليوم الأول**، تعديلهم بعدين مؤلم.
6. **قيس قبل ما تحسّن.**
7. **كل قرار كبير ليه ADR** (سبب ومقارنة).
8. **بسيط قبل ذكي:** قواعد قبل ML.

## 9. الافتراضات والقيود

- الفريق: **شخص واحد + AI Agents**، بدوام جزئي.
- ميزانية البنية التحتية في الـ MVP صغيرة (سيرفر أو اتنين مُدارين).
- مفيش Hardware خاص: حساسات و Gateways جاهزة.
- **افتراض أساسي لسه ما اتثبتش:** إن العميل هيدفع اشتراك. ده أول حاجة بتتختبر.

## 10. أكبر المخاطر على مستوى الرؤية

| الخطر | ليه خطير | التخفيف |
| --- | --- | --- |
| مفيش عميل مهتم يدفع | تبني منتج محدش عايزه | Validation قبل الكود الكبير |
| ربط الأجهزة أصعب من المتوقع | هو أصعب جزء في السوق | حساسات و Gateways جاهزة، وتضييق البروتوكولات |
| Scope creep | المشروع مبيخلصش | قسم "خارج النطاق" + ADR لأي إضافة |
| الاعتماد على شخص واحد | إرهاق أو توقف | Milestones صغيرة قابلة للتسليم |
| تسريب بيانات بين العملاء | تنتهي الثقة فورًا | RLS + اختبارات عزل تلقائية |
| منافسة منصات كبيرة | سعر وإمكانيات أكبر | تخصص قطاعي وخدمة أقرب |
| الإفراط في الكود المولّد بالـ AI | ثغرات وديون تقنية | مراجعة كل Diff، واختبارات، ومراجعة أمان يدوية |

## 12. مصطلحات

- **Asset:** الأصل المراقب (مولد، ثلاجة...).
- **Sensor:** حساس بيقيس قيمة (حرارة، اهتزاز...).
- **Telemetry:** القراءات المرسلة من الأجهزة.
- **Tenant:** شركة عميلة ببياناتها المعزولة.
- **Anomaly:** سلوك غير طبيعي في القراءات.
- **Threshold:** حد ثابت لتفعيل التنبيه.
- **Alert:** تنبيه ناتج عن قاعدة.
- **Work Order:** أمر صيانة.
- **Gateway:** جهاز وسيط بيجمع قراءات الأجهزة ويبعتها.
- **ICP:** ملف العميل المثالي.
- **MVP / Pilot:** أصغر نسخة تثبت القيمة / تجربة على عميل حقيقي.
