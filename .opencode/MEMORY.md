## Lessons & gotchas earned (append only)

1. Bulk `mv` with globs slipped: v0.1's 10–12 were overwritten before archiving — recovered from conversation record. **Defense: explicit file lists + `ls` after every bulk move.**
2. System dotnet 8 + user PATH ordering: always `export PATH="$HOME/.dotnet:$PATH"` in fresh shells; `~/.bashrc` has the permanent fix.
3. Sudo needs the user's password: scripted installs hand the command to the user via `scripts/install-docker.sh` — never attempt sudo non-interactively.
4. Testcontainers throws *before* meaningful messages when docker isn't running: docker availability must be checked explicitly (socket file + `DOCKER_HOST`) before container start, else the "skip" becomes a false failure.
5. xunit v2 in this repo: no `TestContext`; use `CancellationToken.None` and `Xunit.SkippableFact` for docker-conditional tests.
6. Testcontainers 4.x: image goes in the builder constructor, not `.WithImage()`.
7. The machine tolerates the dev stack — **measured 2026-10-27: postgres-only lean up = 36 MB (cap 1 GB), CPU ~5%**. Full-stack number to record at P3.
8. Group-based docker access in the same session that ran usermod: `sg docker -c "<cmd>"` activates the docker group per-process — workaround until a real logout/login makes plain `docker` available everywhere. Testcontainers inherits it inside `sg docker -c "dotnet test ..."`.
9. **Verified 2026-10-27: a fresh terminal (opened after install) gets the docker group without logout** — the user ran plain `dotnet test` (Testcontainers connected straight to the socket, 6/6 green) and plain `docker compose ps` works. `sg docker -c` remains the fallback when old shells deny access.
10. **`gitignore` never untracks** — it only prevents *future* commits; tracked files need `git rm -r --cached` to leave the tree.
11. **git-filter-repo unlinks the origin remote by design** — after a rewrite, `git remote add origin <url>` again before pushing. Also `--prune-empty auto` drops commits that touched only removed paths (history 18→5 here). Used a local backup branch (`backup-pre-rewrite`) as the undo cord before force-push.
12. **Ferry homecoming is not automatic** — merging on GitHub changes origin only; the local side still needs `git switch main && git pull`. And main had **no upstream** after the history rewrite, so `git pull` was silently a no-op until `git branch -u origin/main main`. Recovery habit: after every PR merge, `git status -sb` must show `## main...origin/main` with no arrows.
13. **Every `@param` needs its `AddWithValue` twin** — a bound-name missing its shell value is NOT a driver error: Postgres receives `@id` as literal text, parses `@` as the legacy geometric operator, and reports "column id does not exist" at the position of `id`. Position forensics + a bound/unbound probe test found it; xUnit raw strings hide nothing but help nothing here.
14. **.NET `Directory.EnumerateFiles` char-class glob `"[0-9]*.sql"` may match NOTHING** on Linux — do glob-free filtering in C# (`*.sql` + digit-start) when mirroring a shell glob like `_apply.sh`'s `[0-9]*.sql`.
15. **Close the reader BEFORE you touch the transaction** — `await using var reader` disposes at scope END, not the line above; `tx.CommitAsync` with an open reader throws `NpgsqlOperationInProgressException` ("A command is already in progress"). Gather rows inside the reader's block; commit outside it. Writes never trip this.
16. **Naked shared strings rot silently** — `"identity:self_deleted"` vs the service's `self_delete` was a one-typo dead branch the compiler can never catch; shared codes live as `const`s with one home (`IdentityErrors`), both sides referencing.
17. **MVC `[FromBody]` is case-insensitive by default**; manual `JsonSerializer.Deserialize` is case-SENSITIVE by default — the dev-caller case law applies to the manual path only.
18. **Postman imports never overwrite** — each OpenAPI import creates a NEW collection; user edits live only in the collection where they were made. Build on the existing collection.
19. **A BYPASSRLS probe that counts logins will catch the superuser lying** — the `postgres` role carries `rolbypassrls AND rolcanlogin` natively (initdb artifact), because superuser bypasses RLS by NATURE, not by the attribute. Honest probe shape: `WHERE rolbypassrls AND rolcanlogin AND NOT rolsuper` → exactly `["nabd_admin"]`. Caught live by the suite container, green after the fix (spec 06 fact 1).
20. **The matrix's target argument is semantics, not ceremony** — `PermissionMatrix.Assert(acting, op, TARGET)`: fleet operations must pass `targetTenantId`, not `acting.TenantId`. It fires first BUT can disagree only on tenant-scoped rows — today role refusal masks it, tomorrow a new matrix row would silently mis-evaluate. Review-observation discipline worked exactly as designed: flagged in chat, owner's hand fixed it (`699c6b2`), test net neutral, honesty kept.
21. **A migration file ending in a comment with no trailing newline SWALLOWS the runner's ledger INSERT** — `cat file; echo INSERT | psql` concatenates when the file's last byte isn't `\n`; the echo lands on the comment line and is silently commented out. The tracker then lies (10 rows for 11 files; dev DB too) and every future rebuild re-applies the file. Fix = one newline; hardening candidate: `_apply.sh` echoes `"\nINSERT..."` and/or lints newline-at-EOF (P6). Found by the G1 rebuild — exactly what the gate is for.
22. **`pg_isready` can win the race against first-boot DB creation** — it answers "ready" on the default `postgres` database while `POSTGRES_DB` creation hasn't finished; the very next `psql -d nabd` then dies with "database does not exist". Wait for the TARGET database (`psql -d nabd -tAc "SELECT 1"` in a retry loop), never the readiness probe alone. Hit by the gate rebuild rig, not by the suite (its fixture binds to the mapped port after init).
23. **MQTT 3.1.1 has no negative PUBACK — silence is NOT acceptance** (the owner's live contradiction, 2026-11-12): a denied QoS-1 publish is silently discarded but still acknowledged, so `mosquitto_pub` exits 0 ("accepted") while the broker threw the message away. Truth lives in MQTT 5 (`-V 5` → `Publish failed: Not authorized` reason codes) or the broker log (`authorization_permission_denied … source: http`). The simulator prints a `seq=N` line only after PUBACK for this exact reason.
24. **A rebuild-from-zero dies at 28P01 unless the role passwords are scripted** — migrations 0005/0011 create `nabd_app`/`nabd_admin` LOGIN but deliberately keep PASSWORDS out (NFR-08); the ops step lived in nobody's hands until the P2 gate caught it. `scripts/db-roles.sh` is now the third idempotent step of every rebuild (apply → roles → emqx). Found by G1 doing its job.
25. **MQTTnet 5.x renamed the 4.x API** — `MqttClientFactory` (was MqttFactory), `WithKeepAlivePeriod`, `MqttCommunicationException` in `MQTTnet.Exceptions`, `MqttClientDisconnectOptionsReason`. Online tutorials (4.x) won't compile; verify the code against the real package before handing it over.
26. **A docker daemon-off suite run looks like mass failure** — ~55 fixture fails in 2 s with `DockerUnavailableException` cascades. Check the daemon FIRST (`docker ps`) before diagnosing any test logic; the suite needs Testcontainers.
27. **The nested collection door is uniform-empty, not 404** — `GET /assets/{id}/devices` on a foreign or non-existent asset answers byte-identical `200 []` (RLS hides the rows; no existence hints). Direct reads stay 404. Observed at the P2 gate; owner rules whether a suite fact pins it.
28. **A `pkill -f` pattern matches your OWN shell if the pattern's text appears anywhere else in the same command line** — today's variant: the restart line `dotnet run --project src/Hosts/Nabd.ApiHost` matched the bracket-escaped kill pattern's regex (`Nabd[.]ApiHost` matches the literal dot), SIGTERM'd the script mid-flow. Defense: split kill and relaunch into separate tool calls, or break the pattern (`'Nabd.ApiHo''st'`) AND ensure no other line spells the target.
29. **EMQX's authz cache TTL is absolute-from-insert, not sliding-on-hit** — measured 2026-11-16: cached `allow` entries seeded at flow start kept serving a dead-door outage for ~28 s until their exact TTL, then the first fresh check hit the resource error.
